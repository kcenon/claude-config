Red Team variant H, re-classified by issue #964 (was deny/25-eval-wrapper): `eval` used to be denied outright because its argument was treated as opaque. The guard now tokenizes the eval payload and runs the same inspection on it, so a benign payload (here `git status`) is allowed, while `eval 'rm -rf /'` is still denied by payload scanning and a payload that cannot be inspected (a bare `$VAR`, unbalanced quotes, nesting past the depth bound) still fails closed.
